# Migrations

sqlx applies these files in order of their number when Chat starts, each in one
transaction unless its first line is `-- no-transaction`. A file that has run is
never edited: sqlx refuses to start when an applied file's checksum changes.
Change the schema with a new file, numbered after the newest one.

There is no `091`: the number was skipped, and it stays unused. sqlx runs any
file it has not yet applied, whatever its number, so a new `091_*.sql` would run
before `092` on a new install and after the newest file on one that already
exists, and the two would not be the same database.

## Conventions

New tables and columns follow these. Older ones that differ keep their names;
do not rename them.

- **Ids** are `UUID PRIMARY KEY`, generated by the API.
- **The person a row belongs to** is `owner_id`, `REFERENCES users(id) ON DELETE
  CASCADE`. A reference kept for the record (who made, changed or decided
  something) is `ON DELETE SET NULL`.
- **Times** are `TIMESTAMPTZ`, named `<event>_at`.
- **A lifecycle** column is `status`; this and other fixed sets of values are
  `TEXT CHECK (col IN (...))`.
- **Every TEXT column has a length check**, `CHECK (CHAR_LENGTH(col) <= n)` or
  `BETWEEN 1 AND n`, with `n` at least what the code writes, or a pattern when
  the value has a fixed form.
- **Indexes** are named `<table>_<columns>_idx`.
- **A single-row settings table** uses `id BOOLEAN PRIMARY KEY DEFAULT TRUE CHECK (id)`.
- **A check added to a table that has rows** is added `NOT VALID` and then
  validated, after checking that the rows in use fit.
