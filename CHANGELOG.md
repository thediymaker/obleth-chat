# Changelog

Each release's section is also its GitHub Release notes.

## Unreleased

**Changes**

- **The sign-in screen no longer loads the signed-in app.** The app shell, the chat store and every page's body now load only once someone is signed in, so the JavaScript a signed-out visit fetches is about half what it was (1,274 KiB to 656 KiB for the home page). The first time a page is opened, its body can take a moment to appear.
- **A streaming reply no longer rewrites its reasoning when it has not grown.** Each progress save sends the reasoning only when it is longer than the last saved copy, and otherwise leaves the saved one as it is.
- **Branding and the font are cached, branding is compressed, and the interface server keeps a few connections open.** Logos and site.config.js are now kept by the browser for 5 minutes and then checked by date, so a replaced logo can take up to 5 minutes to show. They are also sent gzip or brotli compressed. The font is kept for a day. API answers stay uncompressed, since they carry sign-in tokens and people's own text. The link to the web interface server keeps up to 4 idle connections for 3 seconds instead of opening one per request, and the metrics library is built without its unused protobuf support.
- **Settings and the status bar share one usage request, and the chat reads capabilities from one place.** Opening Settings asked for your usage twice, once for the page and once for the status bar. Both now read the same copy, which a finished reply refreshes. The chat no longer keeps its own copy of the server's capabilities, and the two Capabilities types are one.
- **The Clusters page lists a person's recently ended Slurm jobs once every 5 minutes instead of on every status check.** The week of ended jobs is a slow accounting query, and the page asked for it with every 30 second status check, for each cluster and each person watching. Each account's list is now kept for 5 minutes, so a job that ends on its own can take up to 5 minutes to appear. A job the person cancels shows on the next check.
- **Watching a chat no longer downloads it again while nothing changed.** Opening a chat now answers with an ETag, and a conditional request gets 304 Not Modified with no body while the chat is unchanged. Chat sends the tag of its last copy when it checks on a reply being written elsewhere or on suggestions, and skips the refresh when the chat is unchanged. A shared chat someone else owns is checked every 4 seconds at first, and the wait doubles up to 30 seconds while it stays the same.
- **A streaming reply no longer re-highlights its open code block or draws collapsed reasoning.** A code block a reply is still writing shows as plain code and is highlighted once its fence closes, instead of being highlighted again on every update. A collapsed Thinking panel draws its reasoning only when opened, so browser find no longer matches text inside a closed panel, and its one-line summary reads only the end of the reasoning. Messages no longer each watch which project the chat is in: Save and Create app look it up when clicked.
- **Code and workspace lists stop redrawing every row while a reply streams.** The Code pane's diff, a workspace's file list and its spreadsheet view were worked out again on every repaint of the chat, and picking a file in a project's Files list redrew every row, up to 5,000. Each is now drawn again only when what it shows changes, and the project's file and commit links no longer load their pages ahead.
- **Pages load less code: the Focus mode switch and the usage chart come on their own.** Every signed-in page loaded the whole chat view, because the header's Focus mode switch lived in it, and Settings loaded the charting library for its one usage chart. The switch is now its own small piece, and the usage chart loads after the page, in a space of its own height so nothing moves.
- **Insights stop polling when nothing can be placed, and say why; a group's member picker searches.** When workstreams could not be placed (no gateway, insights off, no labelling model, or no administrator to run as), the admin Insights page still counted chats as waiting and reloaded its heaviest summary every 15 seconds for as long as it was open. The summary now reports nothing waiting and the reason (`workstreams.stalled`), which the page shows, so it stops reloading. A group's "Add a member" list loaded the first page of every account; it now asks for up to 25 accounts matching the search, and leaves out those already in the group.
- **A PDF is written to disk once to be read.** Reading a PDF wrote it to a temporary file for `pdftotext` and again for `pdftohtml`; both now read the same file. The text is unchanged.
- **Stop takes effect at once, and a running reply stops asking the database every second.** Each running reply asked the database once a second whether it had been stopped. Stop (in the page, from MCP, or by leaving a temporary chat) now sends a wake-up that reaches the reply on any replica, which then stops at once; between wake-ups the reply only renews its lease every 10 seconds, and that renewal also notices a Stop whose wake-up was lost, so the worst case is 10 seconds. The check that the sign-in or token that started a reply is still live runs every 15 seconds as before. Approvals still wait as they did.
- **Reading a chat no longer waits on its owner, and a shared chat answers "not modified".** Every read of a chat (the page's polls, MCP `get_chat`, Stop) took its owner's lock in a writing transaction, so a read waited behind anything else that person was doing. A read is now one read-only snapshot without the lock; only a chat whose reply lease expired, or an imported chat not yet linked, is repaired under the lock first, and Stop, MCP `stop_chat` and Auto mode recover expired leases directly. `GET /api/shared/{id}` now sends an `ETag` with `Cache-Control: no-cache` and answers `304 Not Modified` to a matching `If-None-Match`, so a viewer's 4-second refresh no longer downloads an unchanged transcript.
- **Expired sign-in records are cleared by the hourly cleanup, and old API tokens are deleted.** Each sign-in deleted every expired session on the server, each single sign-on start every expired sign-on attempt, each sign-in-link every expired link and each login attempt the old attempt counters, while revoked and expired API tokens were never deleted. The hourly cleanup now removes all of these, and deletes API tokens revoked or expired more than 30 days ago (the list never showed them; their Activity entries stay). Expired rows can now live up to an hour longer, which changes nothing, since every read checks expiry. The admin Workspaces page no longer reads every workspace session ever recorded: migration 086 indexes when sessions stopped, so it reads only those that overlap the period shown.
- **A running research experiment is looked at less often as it goes on, and written only when its log moves.** Each running run was looked at in its workspace every 10 seconds, one after another, and its 32 KB log tail was written to the database each time, changed or not. A run is now looked at every 5 seconds in its first minute, every 15 seconds up to 10 minutes and every 30 seconds after that, up to four at once, and its log and metrics are written only when they changed. A long run's status can show up to 30 seconds late.
- **Memory reads a chat once it goes quiet, not after every reply.** With memory on, every finished reply sent the person's new messages to the memory model, doubling the model requests of a busy chat. Memory now reads a chat once it has been quiet for 5 minutes, as insights already did, so a conversation costs about one memory request rather than one per reply; a message that asks in so many words to remember or forget something is still read right after its reply, with the "Memory updated" note. Memories from ordinary chats appear a few minutes later, and only chats active in the last day are read when memory is first turned on. Migration 085 adds an index for finding quiet chats, and Administration › System › Memory says how often the model is asked.
- **The insights worker finds chats to label without reading their messages.** Every minute, on every replica, the worker found the newest message of every chat active in the last 30 days. Each chat now records when its newest message arrived (migration 084 adds `conversations.last_message_at`, kept by a trigger on new messages, and fills it for the chats of the last 31 days, which can take a while on a large install), and the worker compares that with the labels. The minute's workstreams check reads its settings, counts and whether any topic waits in one query, and skips placing when nothing waits; finding the workstreams again with the same names and descriptions keeps the chats' places instead of placing every recent chat again.
- **Indexing a document rides out a busy gateway and resumes where it stopped.** A document was embedded one batch of 16 passages at a time, and one refused batch failed the whole document; Retry then embedded it again from the start. Each batch is now tried up to three times when the gateway is busy, errs or times out, three batches are embedded at once, and Retry or a restarted worker carries on after the passages already stored (a change of embedding model still starts again). The idle knowledge worker no longer looks for work every 2 seconds: an upload, a retry, a saved item waiting for its embedding or a change of embedding settings wakes it on every replica, and otherwise it looks every 30 seconds. It checks the embedding settings once a minute instead of on every pass, and leaves emptying the file trash to the files worker, which already did it.
- **Saving a reply in progress writes less.** Each progress save took five round trips to the database, and past 32 KiB a slow reply was rewritten in full every 3 seconds, so a long reply cost far more writes than its size; each tool step also copied the whole activity log before saving it. A save now sets both of its time limits in one statement, a reply past 128 KiB is saved again only when it has grown by a quarter, and the activity log is saved without a copy. If a replica stops mid-reply, a long reply can lose up to that last quarter of its newest text, where it lost up to 3 seconds before.
- **Single sign-on with forwarded tokens costs fewer database round trips.** With `OBLETH_CHAT_GATEWAY_AUTH=forward`, every signed-in request read the session and then, separately, its provider grant, and every gateway call checked the person's identity before reading the grant. The session and API-token checks now read whether the grant's access token has expired in the same query, and ask further only when it has; a gateway call reads the sign-in's own grant first and checks the identity only when there is none. Nothing changes in when a sign-in ends.
- **Chat asks the gateway for its model list once every 15 seconds, and signs fewer tokens.** Every message, follow-up and worker fetched the gateway's model list (two requests) before doing anything, and every gateway request signed a new token. Each person's model list is now reused for 15 seconds, and requests made at the same moment share one fetch; each person's signed token is reused until it has less than a minute left. The request sent for each model step is no longer copied first. Models added or removed on the gateway appear in Chat up to 15 seconds later; the admin model list always asks afresh.
- **The usage page reads the usage rows once.** `GET /api/usage` scanned the last 30 days of a person's usage four times on five connections, and read their limits in a transaction; today's and the 30-day totals now come from the daily rows, and the limits from one plain query, so it is two scans. Starting a reply released abandoned reservations twice; it now does so once. The answer is unchanged.
- **Saved-item and memory search stop keeping indexes they never used.** Both searches compare a person's own rows exactly, so the vector and word indexes on saved items and the word index on memories only cost work on every save. Migration 083 drops them and adds the index the memory worker's backlog lookup needs; results are the same. While memory is off, the worker no longer embeds waiting memories; it catches up when memory is turned on.
- **A reply starts sooner: the question is embedded once, and a full server says so at once.** Knowledge and memory each embedded the person's message, one after the other, before the model was asked; they now look things up together and share one embedding of the question, and memory embeds nothing for a person with no memories to rank. A send while Chat is at its stream limit was answered 429 only after the model catalog and the chat's tools were looked up; it is now refused before either. After a reply, follow-ups, labels and memory are scheduled together, so `done` arrives sooner, and the model's trust level and the person's model-suggestion setting are read once per turn instead of again mid-turn.
- **Compose passes every setting it supports, and blank means unset.** `deploy/compose.yaml` passed a fixed list of settings into Chat, so most of what `.env.example` documents (object storage, connections, Auto mode, file limits, the embedding model, group mapping) was silently ignored there. It now passes all of them, and Chat treats a blank value as unset everywhere, so an empty one in `.env` takes the default instead of stopping startup (an empty `OBLETH_CHAT_MAX_FILE_MB` did). `.env.example` documents those settings and marks the ones Compose cannot use: the branding and secret-key files it does not mount, workspaces and the browser, which need Kubernetes, and the embedding prefixes, which it cannot leave unset (choose them in Settings › Knowledge instead).
- **The Chat pod drains before it stops, and the bundled Postgres fits the pools.** The Chat container now pauses 10 seconds after it is told to stop, as the interface already did, so the Service stops sending it requests before it closes its listener; the grace period is 60 seconds to match. The bundled Postgres, in Compose and `k8s-postgres.yaml`, starts with `max_connections=200` (was 100) and `shared_buffers=256MB` (was 128 MB), with a 512 MiB memory request, and the manifests say that every replica's pool during a roll must fit under it. The bundled Postgres restarts once.
- **The sample alerts fit the sample scrape config.** `OblethChatReplicaUnavailable` wanted two healthy targets, so it always fired against the shipped single-target scrape config. It is replaced by `OblethChatDown`, one alert per scraped process (`up == 0`), and `OblethChatMissing`, when nothing is scraped at all; `prometheus.yaml` adds a Kubernetes pod-discovery job to use instead of the static target. `OblethChatBackupStale` moves to `prometheus-alerts-backup.yaml`, to load only where a backup job writes the status files. Silences and routes on the old alert names need updating. CI checks the samples and tests the rules with promtool.

**Fixes**

- **A search of several words reads only the searcher's own chats.** History search for two or more words looked each word up in every user's messages before narrowing to the searcher's, so a common word cost a scan of the whole instance's history. Each word is now looked up only in the searcher's own messages. On a test instance with 1,000 people and 200,000 messages sharing the same words, one person's search went from 538 ms to 13 ms; the results are the same.
- **The benchmark keeps every run it finished.** `bench/run.py` wrote results in the order it started the runs, so finished runs waited unwritten behind a slow one and were lost if the benchmark was stopped. Each result is now written as soon as it finishes, as the certification runner already did; the results file is in finishing order.

## v1.6.0

**New**

- **Every file can be reached from Your files, and collections page their documents.** Your files listed the newest 100 and stopped, so a person at the 500-file quota could not reach or delete the older ones; a collection listed every document at once. Both now page (`?offset=&limit=`, with `more` in the answer, the shape the Library already used) and the interface offers "Show more". The attachments list answers `items` where it answered `attachments`, and still carries `limits` for one release; the composer reads the limits from `GET /api/attachments/limits` instead of listing the files to find them.
- **Lists say when they were cut, and the People tab pages instead of stopping at 1,000.** Sent feedback stopped at 200 with no way on; a group page listed 500 members and 50 shared chats and a project page 50 chats without saying whether more existed; the admin usage list could report `hasMore` but offered no way to follow it. Feedback pages (`offset`/`limit`, `more`), the group and project pages carry `moreMembers`/`moreChats` and say so, the usage list takes `offset`, and the People list (`GET /api/admin/users`) pages by cursor (`limit`, `after`, `hasMore`, `nextCursor`, 100 per page) like group members, with "Load more people" in place of the 1,000-match notice. The Activity list takes the same `after` cursor; `before` still works for one release.
- **Batches and the Library reach older items, and a running batch is polled on its own.** The Batches page refetched the whole list every 3 seconds while anything ran (one gateway call per refresh), and neither it nor the Library could show anything past the first page. The list now refreshes every 30 seconds and loads older batches on request (`GET /api/batches` takes `after` and answers `nextAfter`); while a batch runs, its progress comes from `?status=active`, one page of running batches, every 3 seconds. The Library offers "Show more".
- **One "not found" page.** A missing project, collection, group, workspace, library item or chat was shown six different ways, and an unknown address got the stock unstyled page. Each now shows the same block (what it is, that it does not exist or is not shared with you, a way back, no Retry), and an unknown address shows it inside the app.

**Changes**

- **Every change to Memory and to the Feedback button is in Activity.** Saving the memory settings and setting the Feedback button mode wrote no audit event, unlike the other settings; both now do, with who changed them. Model certifications, which were written but could not be filtered or read as a sentence, now appear under Settings. The audit log has one writer and one table of its actions, so an action cannot be written in one place and left out of the filter in another; stored names are unchanged.
- **Every API answer is JSON, and every request body is checked for unknown fields.** A malformed body, a wrong content type, a bad id in a path, a body over the limit or an unsupported method on `/api` or `/mcp` was answered in plain text or with no body; each now carries the same `{"error":{"message":…}}` envelope with its status, in Chat's words (never serde's). An unknown `/api` path answers 404 for every method, not 405. The 29 request bodies that still ignored fields they did not know now refuse them like the other 65, so a typo in a client is answered instead of ignored; the cluster agent's three messages keep accepting extra fields, since agents already installed send some. The web interface reads the one envelope.
- **Knowledge uploads are kept the way every other file is.** A knowledge document's object was stored outside the pending-trash protocol, so a crash between the upload and its row left an object nothing ever deleted; it now goes through the same placement as attachments, and an object whose row never commits is swept after the grace period. Both upload paths share one size setting (`OBLETH_CHAT_MAX_FILE_MB`, which the admin setting already governed for attachments), one filename rule (path separators become `_`, at most 200 characters, on attachments too, which used to refuse them), one wording with sizes, and one status per condition: 413 too large, 409 for a full quota or document count (was 413 and 400), 503 when storage is unreachable (was 502). `OBLETH_CHAT_KNOWLEDGE_USER_MB` is read with the other file settings. Knowledge files Chat serves itself are streamed instead of held in memory, and an object store read is refused by its declared size before any of it is buffered.
- **One rule for destructive actions.** Deleting a generated image, revoking a sign-in and ending a cluster file session acted on the first click; now each asks first, like deleting a group or a preset. Every such trigger is the same outlined red button, a confirmed action is toasted, and a failed End session shows its error instead of failing silently. Reversible actions (archive, turn off, detach) still act at once.
- **Numbers, sizes and times read the same everywhere.** Counts, token amounts, file sizes and relative times were each formatted by several private helpers that disagreed on one screen (48k beside 48K, 2 KB beside 2.0 KB, 64 MiB beside 1.0 GB, "1 requests"). One set in lib/format now serves every page: thousands are K, sizes are 1024-based KB/MB/GB as the server words them, list rows say "5 min ago" and detail views give the date, and the period pickers default to 30 days (Usage, Insights and Workspaces offered 28). Some displays change their casing or units accordingly.

**Fixes**

- **Every upload is taken in the same way.** An attachment upload that was refused (not signed in, no size, too large) was answered while the browser was still sending, which a proxy in front reports as a bad gateway instead of the refusal; and once admitted it could hold its share of upload memory for as long as the sender liked. Attachments now drain a refused body first and give up after 30 seconds without a byte or 15 minutes in all, like imports; knowledge files and batch spreadsheets get the same 15-minute total instead of their own 5 minutes. An attachment's bytes are hashed once, on a worker thread, and the bucket's request is signed with that hash instead of hashing again.
- **Old batch spreadsheets are removed for everyone, and starting a batch no longer stalls other work.** A batch's stored rows and labels were expired only when their owner opened the Batches page, so the spreadsheets of people who never came back were kept past the 35 days for good; the hourly cleanup now removes them for every account, and Activity counts them. Starting a batch parsed, checked, rendered and packed a spreadsheet of up to 96 MB on the threads that serve every request, with about three copies in memory; that work now runs on a worker thread while the start holds its reading turn, and the file is sent to the gateway as it is rather than copied into the upload. A third start arriving while two are being read is told to try again in a moment after 30 seconds instead of waiting without a word.
- **Section tabs and the composer fit a phone.** The tab bars of Settings, Library, projects and collections overflowed on a phone and panned the whole page sideways; they now scroll on their own and open with the active tab in view, Administration uses the same bar instead of its own, and a project's Code tab stays highlighted on History, Files and Compare. In the composer, a model name longer than a few letters pushed the Workspace and Browser buttons onto a second line; the buttons now stay on one line and the model name is cut shorter on a phone instead.
- **Typing stays smooth while a reply streams or a device prints.** Every streamed word re-rendered the whole chat page (composer, side pane, status bar and dialogs), and every chunk an attached device printed did the same; only the transcript repaints now, and a device's output reaches the chat page once, when it starts, and then on open, close, lending to a flasher or an error.
- **Editing a large workspace file no longer cuts it down.** The model's **edit_file** read a file through the command runner, which keeps only the last 256 KB of output, and then wrote that tail back as the whole file. **read_file** showed the same tail numbered from line 1. Both now read from the start and know when a file goes on; an edit of a file over 1 MB is refused with a reason instead of written short.
- **A reloaded chat keeps its model.** Opening a chat by its address could leave the model picker, and the next message, on the default model when the model list arrived after the chat. The chat's own model is picked once the list is there.
- **One refresh per burst of edits.** While the model wrote files, the Files tab emptied to "Loading files…" and listed the workspace again on every single write, and the Git tab asked for the chat's Git state twice per change (once for the tab label, once for the tab), each a command in the pod. The Files tab now keeps its rows and reloads once after the edits settle, and the Git state is fetched once per burst.
- **A failed single sign-on brings you back to the sign-in screen.** When single sign-on failed (an identity no administrator had provisioned, a disabled account, a sign-in that took too long or was retried, the provider down, too many attempts), the browser was left on a page of raw JSON at an /api/ address. The sign-in screen now shows what went wrong, and takes you back where you were going once you sign in. Messages say "single sign-on" everywhere a person can see them; "OIDC" is kept for the configuration error that names its variable.
- **Attached files are read after the turn is recorded, not under the lock.** Starting a turn read every replayed image (and document, for a vision model) from file storage while holding the owner's row lock and a pooled database connection, so a slow bucket stalled that person's other requests and, at scale, the replica's database pool. The lock now covers only the rows and the limit checks; the bytes are fetched once the turn is committed (a read that fails ends the turn as an error). The context-size check no longer base64-encodes every image twice per turn: it is computed from the file's size. Export reads bytes the same way.
- **Connection results are cut from the right end.** Every connection tool's result was cut to its first 48 KB, so Kubernetes **logs** lost the newest lines (with the default 200 lines, as soon as they averaged over about 245 bytes), a device's **read** lost the latest output, and a long file read in parts lost a few bytes at every part boundary because the part plus its header ran past the cut. Logs and device output now keep their newest lines; a file is read in 46 KB parts that end at a line (or a character), so "more follows at offset N" is exact and the parts join back into the whole file. The cluster agent's own read limit follows; an older agent is still asked for parts that fit.
- **Deleting a chat is quick again at any size.** Each deleted message made Postgres scan five tables for links back to it, because none of the columns that point at messages had an index; a long chat could run thousands of scans under its owner's lock, and the hourly retention pass could hit its 10-second limit. Migration 080 adds the five indexes (plus two that let the file-moving worker see at a glance that nothing is left to move; it now also waits up to five minutes between empty passes instead of 30 seconds).
- **An asleep workspace is left alone.** A chat with a workspace that had gone to sleep asked Chat about it every two seconds for as long as the chat was open, redrawing the page each time. It is checked once, and again when something wakes it.

## v1.5.2

**Fixes**

- **A device's serial monitor is a terminal.** A board's console that printed colours or redrew a status line in place, such as apt's progress, showed stray codes (`[33m`, `[0m`) and piled every redraw onto one line. The monitor now draws the output in a terminal, as a console would, and keys typed into it go to the device as they are, Ctrl+C and arrows included. **Send a line** stays for line-at-a-time firmware.
- **The model reads a console as plain text.** The device's **Read output** tool returned the same codes and every redraw of a progress line. It now returns each line as it last stood, without colour or cursor codes; a code split across two reads waits for the rest, and a wait for text such as a coloured prompt matches.
- **Settings no longer scrolls past the page.** The window kept scrolling into empty space below Settings › Personal. Each checkbox in the Favorite models list keeps a hidden form input beside it, and those inputs were placed against the window instead of the list, so a long model list stretched the window. They now stay inside the list, and nothing on any page can stretch the window below the app.

## v1.5.1

**Fixes**

- **A file session waits on a notification, not on the database.** Every waiting call and every session job polled the database on a short timer, so a thousand idle sessions would have cost the database a steady stream of queries. The job now holds one request to Chat at a time, up to 50 seconds, and Chat wakes it through a Postgres notification (`LISTEN`/`NOTIFY` on `obleth_chat_wakeups`) the moment a call is filed; a result, a session's end and a change of the cluster's directories wake their waiters at once on every replica. An idle session costs no queries, and a thousand of them cost about twenty requests a second. A session now ends after 20 idle minutes instead of an hour. Chat's database connection must allow `LISTEN`, so it cannot run through a transaction-pooling proxy.
- **Disk usage on a cluster is measured with `du`.** Summing a large directory file by file in Python took half a minute for a terabyte and looked like a stalled chat. Where `du` exists the agent uses it (a 1.4 TB scratch tree takes a few seconds) and walks the tree itself otherwise, checking its time limit as it goes; the tool tells the model a large tree takes a while and a subdirectory answers faster. A session busy with one long operation does not poll meanwhile, so a new call during it no longer takes the session for gone after two minutes and starts a second job: the threshold is five minutes, longer than any one operation may run.

## v1.5.0

**New**

- **Files on a Slurm cluster.** With **Reach files on the cluster** ticked on a Slurm connection, the model can list, find, read, search and measure each person's own files there, write files, move them, and move them to a trash directory, as that person and nowhere else. The first call in a while starts a small job as the person through slurmrestd with their own token; the job connects out to Chat, carries out the chat's file operations one at a time under the directories the cluster allows (`~` by default; `~,/scratch/$USER` for a scratch space), and exits once idle for an hour or at its time limit. Nothing on the cluster listens, no shared account reads anyone's files, and a job whose account is not the person's ends the session. Writes, moves and trashing wait for **Allow** like any other change, with the path and size on the card; the trash is `~/.chat-trash/<date>` on the cluster, where files keep their paths and can be moved back. The connection takes the partition and QoS for the session job (a small one that starts within seconds), the session length in hours, and the directories the model may reach. The compute nodes need `python3` and must reach Chat's address (`OBLETH_CHAT_ORIGIN`). The Clusters page shows the person's own file session under the cluster, with its job, node and last call, and **End session**, which cancels the job; `GET /api/connections/{id}/status` carries `fileSession` and `DELETE /api/connections/{id}/file-session` ends it. Certification gains six files cases (K06 to K11), two of them a file holding instructions the model must not act on, with their fixtures under `evals/certify/fixtures/cluster-home`. Migration `075` adds `cluster_sessions` and `cluster_calls`. Over the API, the session job uses `POST /api/cluster-sessions/hello`, `GET /api/cluster-sessions/next`, `POST /api/cluster-sessions/calls/{id}` and `POST /api/cluster-sessions/bye` with its own session token.
- **Decisions can allow a change the person asked for.** Before the Allow card for a cluster change that only adds something (a job submission, a new file, a move), Chat puts four yes/no questions to a [decision](https://www.obleth.com/docs/run-chat/decisions): did the person ask for it in their own messages, does it stay within that request, does it keep existing data, and could they undo it. A sure yes to all four (over 70% each) runs the call without the card; the step says "allowed by a decision" and keeps the answers. Anything else, a doubt, an unanswered question or no answer at all, asks as before. Changes that delete or replace something (trash, overwrite, cancel, Kubernetes apply and delete) and tools of other services always ask. The judge reads only the person's own messages and the card, never what the model read from files or pages, and the model is told that text from files on a cluster is data, not instructions. Administrators turn it off with **Let decisions allow changes the person asked for** in Admin › System › Decisions. Migration `076` adds the setting, on.
- **How far each model is trusted with changes.** Under Admin › Models, **Changes through connections** is decided from the model's certification score unless set by hand: a model at 90% or more is **certified**, so a decision may let a change it proposes run unasked; below that, or not certified yet, it is **provisional**, and every change asks; **blocked** offers it only the tools that read, and tells it a change needs a certified model. Chats on `auto` count as provisional. Certification scores come from `evals/certify/publish.py`, which sends each model's result to `PUT /api/admin/model-certification/{model}`; the model editor shows the score, the cases and the date. Migration `077` adds the setting and the score.
- **A better suited model, offered once.** When a chat on a model that is not certified for changes first reaches for a cluster or workspace tool, the reply carries a card: this model is not as well suited to work like this, and the best certified model the person can use did better, with its score. **Switch** uses that model for this chat from the next message on; dismissing keeps the model; **Don't suggest models again** turns the offers off, as does **Suggest a better suited model** under Settings › Appearance. Nothing is forced, and nothing is offered when no certified model is available. Each offer and its outcome is kept in `model_suggestions` (migration `078`), so the offers can be judged.

**Fixes**

- **A question about a cluster no longer goes to a device.** Asked about a cluster it had no tools for, with only a board attached, the model took the board for the cluster and tried to sign in to it. The model now hears about every connection the person has that the chat cannot use yet, with what is missing: a shared cluster without the person's own token, one they turned off, or one off in this chat, each with the page where they fix it. It is told never to use one service as a stand-in for another on a guess: a system none of its tools covers is not connected, and it says so. A device is a board at the person's computer, never a cluster or a remote server; work the person asks for on the device still runs there, network included. A chat with no tools at all still hears about such connections.
- **A file session job that cannot reach Chat says so at once.** The job's output goes nowhere, so a job that ended in its first second, for instance on a node that could not look up Chat's address, left the call waiting out the full 10 minutes and then blaming a busy queue. While a call waits for its session to start, Chat now looks the job up every 5 seconds (each look bounded, so a slow slurmrestd does not hold the answer up, and only the session's own job counts, not an older one with the same id). Once it has ended, the call ends with how and why, read from its state and exit code: the node could not look up Chat's address or connect to it (the job connects straight to Chat, without a proxy), the server at Chat's address turned it away or answered with an error, the node has no `python3` or one older than 3.6, or the job was cancelled, ran out of memory or lost its node. The agent and the job script exit with their own codes for each of these (3 to 8). A job Slurm will never start, such as one longer than its partition allows or with a QoS that does not exist, is cancelled at once with what an administrator changes. A start that does run out says whether the job was still queued, with Slurm's reason, or running without reaching Chat. A path outside the session's directories is refused with the directories one to a line, what `~` stands for, and a mark on any that do not exist on the cluster.
- **Changing a cluster's directories takes effect at the next call.** A running session job kept the directories it was started with, so a corrected setting changed nothing until the session idled out an hour later. Each session now records its directories; when the cluster's setting differs, the next call ends the session (its job stops at its next poll) and starts a new one. Migration `079` adds `cluster_sessions.roots`.
- **The Allow card for a device says the device.** It said "It changes the cluster" for every change outside MCP; a device change now reads "It changes the device, so it waits for you. Your browser sends it."

Over the API, `GET /api/conversations/{id}/workspace/download` takes repeated `path` parameters (up to 200, and 64 MB in all).

**Changes**

- **Memory keeps only what lasts.** Memory kept details of the task in front of it as facts about the person: a file name, a goal for one experiment, a preference stated for one deck. Every memory it would add or change is now put to a [decision](https://www.obleth.com/docs/run-chat/decisions) first, which asks whether it is a lasting fact the person's messages state, worth knowing in chats about other things weeks from now; only a yes over 50% is kept. On a set of 20 proposals, the gateway's verdicts model and gemma4-31b-it each dropped all 10 task details and kept 9 of 10 lasting facts. Migration `072` adds the setting, on.

**Fixes**

- **A memory's new topic shows with the memory in it.** A topic was saved before the memory was linked to it, so the Memory page could briefly show a topic with no memories.

**Security**

- **The web interface is reached only at its own address.** Chat sends every request that none of its own routes answers to the interface server. A request path written as `//host/…` or `/\host/…` was resolved to that host instead, so Chat would fetch any address it could reach and return the answer from its own origin, cookies included. The address is now always the interface server's, only page loads (`GET` and `HEAD`) are passed on, the session cookie and other credentials stay in Chat, and the interface server cannot set cookies. Installs behind a proxy that rewrites such paths (Traefik does) were not reachable this way from outside.
- **Large uploads are read after sign-in.** Starting a batch and adding a file to a knowledge collection read their bodies (up to 96 MB and 50 MB) before checking who was asking, so anyone who could reach Chat could fill its memory. Both now check sign-in first, a batch's rows and columns are counted while the spreadsheet is read instead of after, two spreadsheets are read at a time, and an upload has five minutes to arrive.
- **An approval covers one tool call.** With models whose tool calls Chat reads from the reply's text, or that send calls without ids, a later call in the same turn could reuse an earlier call's id and run on its Allow (or be refused on its Deny) without a card. Every call in a turn now has its own id, each question starts unanswered, and an answer is used up when it is read.
- **Shared chats keep the owner's memories private.** What Chat recalled or learned about the owner while answering was part of each reply's activity, which a shared chat showed and a fork copied. Viewers and forks no longer get those entries. A fork also copies only the generated images the shared replies show, not ones from replies the owner regenerated or branched away from.
- **Kubernetes tools take names, not paths.** A namespace, resource name or API version went into the request path as the model wrote it, so one containing `/`, `..`, `?` or `#` addressed something else on the cluster's API, such as a pod's proxy or a whole collection, and the read tools ask for no approval. Each is now checked to be a name of its kind, and no request leaves the cluster address the connection was saved with.
- **An approval card shows what will run.** The card for a Kubernetes or Slurm change was worked out in the browser from the text of the call's arguments, with the text itself folded away and cut at 2 KB. A crafted call could make the two differ: a script line that looked like a field ended the script shown, a manifest after `--- # comment` was applied but not listed, and an extra argument could supply the name a delete appeared to target. The summary now comes from the server, from the same reading of the arguments that carries the call out, and every argument is shown in full and in view, for other services' tools too. A call whose arguments are too long to show whole (384 KB) is refused, and Chat's own tools that change something refuse arguments they do not name.
- **Importing chat history stays within memory.** A small export file could ask for many times its size once parsed, or inflate from a zip, and one upload could take the server down. Each conversation is now held to an allowance as it is read (64 MiB for its bytes and what is kept of them), fields Chat does not use are skipped instead of kept, and an import keeps at most 256 MiB of text (was 768). The file with the conversation that goes over is refused with a message saying so. An upload that stops arriving is dropped after 30 seconds, so it no longer holds the one import that runs at a time.
- **Reading documents takes time and memory that follow their size.** A web page of unclosed headings or math took time that grew with the square of its length (minutes for a megabyte) on the threads that answer requests, and a workbook or deck of empty elements took most of a gigabyte. Pages are now read in one pass, elements are read as they are needed, a document is split at up to 10,000 headings and reads up to 10,000 PDF bookmarks, and all of it runs off the request threads. `pdftotext`, `pdftohtml` and `unzip` run with a 1 GiB memory limit and without Chat's environment, which holds its keys.
- **Batch results are written out as they are read.** Downloading a batch's results held the gateway's output file, every answer and the finished spreadsheet in memory at once, up to 512 MB a file, for as many downloads as were asked for. Answers are now read a line at a time and the spreadsheet is sent a few hundred rows at a time, two downloads run at once, and a download reads at most 192 MB of results.
- **A tool call the model only shows is not run.** For models whose tool calls Chat reads from the reply's text, a call inside a code block, a code span or a quoted line ran like any other, so a reply that quoted a page or file holding one ran it. Those are now left as text. A call's own arguments may still hold code blocks.
- **Revoking an API token stops the reply it started.** A reply started over MCP kept running, tools included, after its token was revoked. It now ends within 15 seconds.
- **Kubernetes `get` shows a Secret without its values:** its keys and the size of each, as `kubectl describe` does. Reading needs no approval and goes to the model, so the values stay on the cluster.
- **A shared connection's address is shown without its path** to people who do not manage it, since the path or query of an MCP server's address often carries its key. The audit log records the address without its query.
- **Drafts end with the session.** What was set up for a chat not yet started (Auto mode, connections switched off, a project, collections) and text typed into Steer stayed in the page after sign-out, for the next person to sign in on it.
- **Knowledge uploads wait for room.** A file's name, type and the person's remaining storage are checked before it is read, and uploads share the memory budget attachments already use, so many large uploads at once wait their turn.
- **Drawings and code blocks cannot hang the page.** Telling whether an `svg` block is a drawing took time that doubled with each comment it opened with, so about 300 characters in any message, a shared chat's included, froze the tab of whoever opened it. It is now one pass. A code block labelled `constructor` or the like is shown as plain code.
- **Batch results:** a cell starting with `-` that a spreadsheet would read as a formula is written as text. List items (`- first`) and negative numbers are unchanged.
- **TLS trust store.** `rustls-webpki` 0.103.16 and `webpki-roots` 1.0.11, which stop trusting two intermediate certificates whose keys are public.

**Deployment**

- **New installs get the current release.** `deploy/compose.yaml` and `deploy/k8s.yaml`, which `setup.sh` applies as they are, still named the 1.0.0 images, so a fresh install ran 1.0.0 whatever was checked out. They now name this version, and CI and the release workflow fail when they do not (`scripts/check-versions.sh`).

## v1.0.0

The first release of obleth-chat: a self-hosted chat app in front of the [obleth gateway](https://github.com/thediymaker/obleth-gateway), where each person signs in with their own account and every request reaches the gateway as that person.

**What's in it**

- **Chat.** A model or Auto, thinking effort, files and images, versions you can step through when you edit or regenerate, branches, temporary chats, read-only and live sharing, and replies that keep running on the server when the tab closes. Replies draw Markdown, math, Mermaid diagrams, molecules, SVG and CSV.
- **Knowledge.** Collections of PDFs, Word files, HTML, Markdown and code, searched with citations that open the source at the passage.
- **Projects.** Shared instructions, documents, notes and chats, with the project's code in one git history, exported as a zip or pushed to GitHub.
- **Workspaces and the browser.** A private Linux pod per person where the model writes, runs and fixes an app, shown in a live preview with files, a terminal and checkpoints; and a Chrome the model drives with the person watching.
- **Connections.** MCP servers, Slurm clusters and Kubernetes clusters as tools, acting as the person's own account. Anything that changes state waits for Allow or Deny.
- **Research and agents.** Research mode runs an experiment tree in a project; worker agents take tasks in the background.
- **Apps.** An administrator turns a project into an app: steps over typed inputs (Agent, Search knowledge, Code, Decide, If, For each, HTTP request, Response), laid out on a canvas, tried as a draft, then published as an API called with a key and as a chat page at `/a/<code>/<name>`. A chat can suggest an app with its first steps.
- **Administration.** Models and who sees them, generation defaults, daily allowances, accounts and groups, usage and insights, activity, feedback, and a site banner.
- **Sign-in.** Local accounts, OIDC, or both. With OIDC, Chat can forward each person's own access token to the gateway. Signing in returns to the page it started from.

**Running it**

- Two servers: the Rust server (`chat` image), which is the front door and answers every API call, and the interface server (`chat-ui` image, Next.js), which the Rust server sends every page request to through `OBLETH_CHAT_UI_URL`. Workspaces and the browser have their own images (`workspace`, `browser`).
- `./setup.sh docker` runs both with PostgreSQL through Compose (`deploy/compose.yaml`); `./setup.sh kubernetes` runs them with workspaces (`deploy/k8s.yaml`).
- Branding is `site.config.js` and `assets/` in the branding folder (`OBLETH_CHAT_BRANDING_DIR`, `/app/branding` in the image), which installs replace with their own.
